# GitHub Portfolio Critic Agent

AI-агент (LangGraph, ReAct-патерн), що аналізує публічний GitHub-репозиторій
і дає структурований технічний фідбек — так, як це робить справжній технічний
рев'ювер перед прийняттям рішення про наймання.

## Чому це "справжній" AI-агент, а не просто виклик LLM

Замість одного фіксованого промта, агент **сам вирішує**, у якому порядку
викликати інструменти:
1. Спочатку дивиться загальну інформацію про репозиторій
2. Потім переглядає структуру файлів
3. **Сам вирішує**, у які конкретні файли варто заглянути (README, тести,
   основний код) — це рішення приймає LLM у процесі роздумів, а не
   заздалегідь прописаний сценарій

Це і є суть **tool-calling агента**: LLM отримує набір інструментів з
описами, і сам, крок за кроком, вирішує, як їх використати для
досягнення мети.

## Інструменти (tools) агента

- `get_repo_info` — загальна інформація (опис, мова, розмір)
- `list_repo_files` — структура файлів у репозиторії
- `get_file_content` — вміст конкретного файлу

## Встановлення

**Через requirements.txt (простіше):**
```bash
pip install -r requirements.txt
```

**Або через pyproject.toml (стандартний спосіб, з dev-залежностями):**
```bash
pip install -e ".[dev]"
```

Отримай безкоштовний ключ Groq на [console.groq.com](https://console.groq.com)
(без картки), створи `.env` на основі `.env.example`.

## Тестування

Проєкт покритий автотестами (`pytest`) з mock'ами для мережевих викликів —
тести працюють миттєво, без інтернету, і перевіряють як "щасливий шлях"
(коректна відповідь API), так і обробку помилок (404, зникле з'єднання,
timeout):

```bash
pip install pytest
pytest test_github_tools.py -v
```

Очікуваний результат: **13 passed**.

Окремо є `test_tools_manually.py` — швидка "ручна" перевірка на реальному
GitHub API (без моків), корисна для діагностики проблем з мережею/ключами,
на відміну від `test_github_tools.py`, який ізольований від зовнішніх
залежностей.

## CI (GitHub Actions)

При кожному push/pull request у гілку `main` автоматично запускається:
- **Lint** через `ruff` (перевірка стилю коду та порядку імпортів)
- **Тести** через `pytest`

Конфігурація: [`.github/workflows/ci.yml`](.github/workflows/ci.yml).

## Швидка перевірка (без LLM)

Перед запуском повного агента, перевір, що самі інструменти працюють:

```bash
python test_tools_manually.py
```

Це протестує GitHub API tools на маленькому публічному репозиторії
(`octocat/Hello-World`), без виклику LLM — щоб одразу зрозуміти,
де саме проблема, якщо щось не спрацює.

## Запуск

```bash
python main.py
```

Введи посилання на будь-який публічний GitHub-репозиторій, наприклад:
```
MAJIbTA26/password-strength-checker-flask
```

## Реальні проблеми, які довелось вирішити під час розробки

Ця секція — чесна історія розробки, а не гіпотетичний опис:

- **`create_react_agent() got an unexpected keyword argument 'prompt'`** —
  назва параметра для системного промта відрізняється між версіями
  `langgraph`. Виправлено: системний промт тепер передається як звичайне
  повідомлення в `messages`, а не через нестабільний kwarg.
- **`Recursion limit of 25 reached`** — агент "зациклювався", повторно
  викликаючи інструменти, не доходячи до фінальної відповіді. Виправлено
  трьома способами одночасно: явний `max_tokens` для reasoning-моделі,
  жорсткіші обмеження в системному промті, і запасний `recursion_limit=50`.
- **Неповне покриття файлів під час аналізу** — агент сам обирав, які файли
  перевірити, і іноді пропускав ключовий `main.py`, даючи фідбек на основі
  неповної інформації. Виправлено: зробили перевірку точки входу програми
  обов'язковою частиною системного промта, а не залежною від вибору LLM.
- **Агент іноді давав неточний фідбек** навіть після виправлень (наприклад,
  стверджував, що файл "обривається в середині", хоча це було не так) —
  реальне, задокументоване тут обмеження LLM-агентів: якість аналізу
  залежить від того, наскільки глибоко модель дійсно "прочитала" файл,
  а не тільки від того, чи викликала вона відповідний tool.

## Обмеження

- Працює тільки з **публічними** репозиторіями (без токена)
- GitHub API має ліміт 60 запитів/год без авторизації — для аналізу
  одного репозиторію цього достатньо, але для масового використання
  знадобиться Personal Access Token
- Вміст файлів обрізається до 3000 символів, щоб не витрачати забагато
  токенів на один файл
- Фідбек агента не завжди на 100% точний (див. розділ вище) — це
  інструмент для швидкого орієнтовного аналізу, а не заміна людського
  code review
